# Slave 已实现功能的补充验收

> 此报告为补验时的历史状态。跨 ID 调度和 AW/W 背压现已实现，最新结果见 [第二增量报告](slave-stage2-report.md)。

日期：2026-11-15（本轮跨日完成）。验收对象是外部 Slave 验证模型，不是 Crossbar RTL。本文区分“已实现并有测试证据”“仅部分验收”“尚未实现”。原第一增量报告保留为历史记录，以本文描述最新验收边界。

## 实际运行结果

常规验收共 60 次达到预期：32 位数据/4 位 ID 的 27 项、64 位数据/4 位 ID 的 27 项、容量 1/2 的 3 项以及 32 位数据/2 位 ID 的 3 项联合/并发测试。包含 8 次预定 fatal 结束的负向用例，另有 2 次精确捕获 CLEAR_BUSY 的测试；不是宣称 60 次都零诊断。

容量 4 用例的实际证据：peak=4、blocked_aw=7、triple=1，最终 AW=5、W=5、B=5。同 ID 用例也实际达到这些边界。三个直连参数配置均完成 AW=12、W=24、B=12。单拍字节矩阵分别完成 50、610 笔。

机器可读汇总见 [slave-acceptance-results.json](slave-acceptance-results.json)。每次运行包含日志路径、工具版本、源码摘要和具体错误码。全部测试使用固定 seed=7；主要为确定性验收，不冒充多种子约束随机回归。

## Verification 的含义与独立性

本轮工作属于仿真验证（verification）：TB 提供输入激励，独立记录接口握手，比较期望字节/响应，并运行协议断言及负向用例。当前首先验证测试环境自身的 Slave 模型是否可靠；之后 Master/Slave/系统 Scoreboard 才用于验证 Crossbar。

实现与 TB 均由助手编写，不冒充第三方独立验证。独立性体现在算法和数据来源：新增事务账本仅依据引脚采样，不读取 Driver 私有队列；预期内存按绝对字节地址枚举，不调用 Slave 地址/提交函数。仍可能存在共同理解规格的错误，用户审查和后续系统验证不能省略。

## 新增验收内容

- 容量：用直接引脚激励占满 4 笔，持续提出第五笔；完成第一笔 W 后仍不能提前释放名额，BREADY 拉低时继续阻挡，释放 B 后新 AW 恢复。另测容量 1、2。
- 同 ID 多笔：按序返回，并让第二笔发生可预期 SLVERR。重复 ID 场景用不同状态区分可观察的顺序，而不只是核对相同 BID。所有同 ID 内部偷换仍不能仅靠接口全部识别。
- 同周期：必须实际观察到同一采样沿 AW/W/B 三种握手，未命中则测试失败。
- 字节：对单拍传输遍历总线内全部起始偏移、全部支持尺寸和所有合法 WSTRB 子集，含全零；32 位 50 笔、64 位 610 笔，逐笔核对内存及周边字节。这不是所有长度 burst 的全组合覆盖。
- 复位：补测空闲、AW 已收但 W 未收、B 延迟期、BVALID 被背压期间的共同复位；保留原有 W 中途复位测试。检查取消事务不返回旧 B，复位后新任务正常完成、已写存储保留。
- 清零：活跃事务期间必须准确报告一次 CLEAR_BUSY 且不清内存；另测共同复位隔离期间清零。预期错误只在测试回调中记录并降为 INFO，遗漏或额外触发均失败。
- 地址窗口：非零 base_addr 下写入，避免只能工作在 S0 地址窗口。
- 配置：容量为零必须准确报告 SLAVE_CONFIG；运行器不把其他 fatal 当成配置检查通过。
- 联合运行：实际实例化已有 Master agent 与 Slave Driver，12 笔、每笔 2 拍，多 ID、Master 上限 2、BREADY 可控暂停。新增观察账本核对接收、响应和最终内存，而不是只看 Master sequence 结束。

## 覆盖缺口的处置

S01 单笔闭环、S02 提前 W、S04 容量边界、S07 同拍事件、S08 拒绝写入、S09 所列共同复位阶段、S10 静止/活跃/复位隔离清零均已有本轮或保留基线的定向证据。

S03 单拍尺寸/偏移/合法掩码组合显著补齐，已有两拍与最大 256 拍样例；其他多拍尺寸/长度/掩码组合和随机压力仍未收敛。S05 覆盖 B 背压及默认/1/3 周期额外延迟，未实现 AW/W 可配置背压。S06 仅通过当前按序实现的多 ID 回传与同 ID 顺序检查，跨 ID 乱序未实现。S11 当前测试账本不等同可复用独立 Slave Monitor；S12 仅精选宽度/容量配置，不保证全参数空间。

## 尚未满足的功能（不是“测试通过”）

- 跨 ID 乱序 B：当前 Driver 始终选择 active_q[0]，cfg 无响应排序模式；应在后续增量实现候选选择、每 ID 队头约束和响应锁定，再验收。
- AW/W 可配置背压：当前 AWREADY 只由容量决定，WREADY 只由已收 AW 决定；尚无周期/随机延迟策略。当前容量背压通过不代表该功能完成。
- 独立 Slave Monitor、active/passive agent：对应可复用组件文件尚不存在。新增验收账本位于 tests 下，不冒称产品化 Monitor。
- 系统路由 Scoreboard：Crossbar RTL 尚未实现，因此不存在四个入口/出口的路由验收证据。直连 Master-Slave 测试不能替代它。
- 原生功能覆盖、代码覆盖及约束随机收敛：仍缺完整报告。定向命中计数不是完整 coverage closure；本机原生 cross 查询限制仍保留。

这些缺口在本次验收中明确标为未满足，未因正常用例通过而删除或降级。

## 冻结 TB 的故障检测检查

另建两个隔离副本，只改 Slave Driver 的一处代码，测试和期望保持原样：

- wrong_bid：返回 BID 异或 1；原 smoke 测试报告 TEST_BID，判定失败。
- wrong_byte：每个写入字节异或 1；原 smoke 测试报告 TEST_MEMORY，判定失败。

两份副本均编译成功、仿真正常结束、无其他 fatal，且仅出现目标错误类型；不是把编译失败或超时当作“发现缺陷”。正式 SV 源码与测试在注入前后的逐文件摘要一致，隔离副本只有 Driver 变化。

两项均被检测到。这仅证明 TB 对这两种指定缺陷有效，不是所有缺陷的检测率，也不能证明实现没有其他 bug。原日志、差异和冻结摘要见 [故障注入证据](../checks/slave-acceptance-mutations/results.json)。这 2 次故意失败独立于前述 60 次常规验收统计。
