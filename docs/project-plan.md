# 项目计划与范围 v0.2

更新：2026-11-12。状态：已确认对话内容的整理稿，非已完成设计。

## 1. 最终目标与交付

交付一个参数化、多 Master/Slave、AW/W/B/AR/R 五通道、独立读写路径、支持 multiple outstanding 与多 ID、具备响应路由和顺序保护的 AXI4 Memory-Mapped Crossbar。路线 B：参考成熟开源架构，自行组织和实现主要 SystemVerilog RTL；不强制所有组件从零重写，复用内容需记录来源和许可证。

验证需形成需求到检查项的对应关系，包含 UVM 环境、独立 Scoreboard、Monitor、协议检查、定向与受约束随机测试、功能与代码覆盖分析、可复现回归及缺陷记录。关键控制逻辑的断言及形式验证范围后续确定。

工程成果需要支持 RTL/DV 面试讨论：架构取舍、ID/order、并发、背压、真实缺陷及修复、验证收敛、吞吐/延迟与资源评估。结论必须与实际测试和工具条件对应。

交付物：设计与接口规格、时序说明、RTL、验证环境、运行入口、测试和覆盖报告、已知限制、性能评估、展示材料。不能将计划功能写成已实现能力。

日期目标：2026-11-30 前形成可运行、可验证、可展示初版；2027 年 1 月简历定稿。阶段安排不等于删除最终功能；若进度冲突，报告差距后共同调整。

## 2. 已确认的首阶段配置

- 外部设备：4 个 Master、4 个 Slave。Crossbar 对应 4 组 S_AXI 与 4 组 M_AXI。
- 先实现 AW/W/B 写闭环；AR/R 留在后续基础功能里程碑，最终必须补齐。
- 地址 32 位，数据 32 位，WSTRB 4 位；保留参数化。
- Master 侧 ID 2 位，默认 ID 与目标 Slave 编号相同：S0/S1/S2/S3 对应 0/1/2/3，便于波形阅读。定向测试允许覆盖 ID。
- 每个 Master 最多 2 笔 outstanding，保留参数化；两个事务可以使用相同 ID。
- 当前来源编码方案：4 个 Master 使用 2 位来源码，附在原始 2 位 ID 高位，下游 ID 为 4 位。B 返回后用来源码路由并恢复原始 ID。
- 同一 Master 的同一 ID 在尚有未完成事务时绑定一个目标 Slave；同目标允许多笔，不同目标等待旧事务排空。不同 ID 可访问不同 Slave并允许 B 乱序完成。
- 每个 Slave 出口默认容量 4，保留参数化。容量满阻止新 AW 转发，不阻止已有 W/B 的推进。
- 多 Master 竞争使用轮询仲裁。具体 grant 保持、指针推进与资源预留时刻需在仲裁模块规格落定。
- 支持单拍和 1～256 拍 INCR burst；支持每拍 1、2、4 字节及合法非对齐起始地址。合法字节位置、WSTRB 和地址边界按协议处理。
- 写数据采用事务记录队列和 2 拍 W 缓冲，逐拍转发，不缓存完整 burst。缓冲具体数量与放置点待模块连接图确认。
- Crossbar 在对应路由记录建立前可以不接收提前到达的 W；Master 必须能产生 W 提前的合法场景。
- 基础阶段单时钟、全系统共同复位。取消待发送与在途任务、清空事务和控制记录，保留已实际写入的存储内容及参考存储状态。独立提供测试环境存储清零操作，与普通 reset 分开；配置、错误历史与累计覆盖率保留。
- 系统级主验证环境使用 SystemVerilog UVM，模块自检可使用轻量环境。

## 3. 地址映射

各 Master 可访问全部四个 Slave。首配置每个 Slave 64KB，区间含起止地址：

```text
S0  0x0000_0000 ～ 0x0000_FFFF
S1  0x0001_0000 ～ 0x0001_FFFF
S2  0x0002_0000 ～ 0x0002_FFFF
S3  0x0003_0000 ～ 0x0003_FFFF
```

映射可配置；其他地址用于 DECERR 测试。地址译码决定目标，不能依靠 AWID 选择目标。

未映射写事务的 W 消耗、B 产生及顺序保护需要单独设计。不能仅因 AW 未映射就提前返回 B 或泄漏 outstanding 名额。

## 4. 模块推进顺序

1. Master 验证模型：先完成模块规格和接口审查，随后仅实现该模型和必要自检支架。
2. Slave 验证模型：存储更新、可控 AWREADY/WREADY、响应延迟、不同 ID 乱序、同 ID 顺序、Monitor。
3. Crossbar 模块连接与接口细化：译码、事务跟踪、ID、AW 仲裁、W 路由/来源队列、B 路由、缓冲、错误响应。
4. 基础模块按依赖顺序逐项实现与自检，再集成 4×4 写通路。
5. 读通路、完整功能清单和系统验证逐步完成；最终交付必须覆盖五通道。

这是推进顺序，不代表所有内部模块已定案。自检支架不是正式 Slave 模型，不借自检之名提前实现下一整个模块。

## 5. 后续增强：故障隔离与恢复

在基础系统和验证完成后单独实施，不阻塞基础交付：

- 增强 1：Slave 卡死/运行中复位的故障注入、检测、隔离、受影响事务处理和恢复。
- 增强 2：Master 运行中故障/复位处理，单独设计和验收。

超时阈值是系统策略；部分写入、旧响应、错误完成、资源回收和正常端口进展都需明确。当前只记录扩展点，不提前编写故障恢复逻辑。

## 6. 实现前或后续需补齐的决定

- 首阶段之外的 FIXED/WRAP、exclusive access、属性语义及其他协议功能逐项列清；不能默认为取消。
- AWLOCK/AWCACHE/AWPROT/AWQOS 的默认值与激励范围；当前保留字段、转发检查，首阶段 QoS 不改变轮询优先级。
- 已确认首阶段不启用 AWUSER/WUSER/BUSER 和 AWREGION；最终是否加入按具体用途另行决定。
- 每个出口 outstanding 容量计数的准确起止事件：下游 AW 接收与 B 在何处接收/保存后释放，待 Crossbar 规格确定。
- 同 ID 目标切换、来源队列、资源预留与多个握手的原子更新时序。
- B 响应路径缓冲、仲裁与复位清理。
- UVM 版本、可运行仿真器、断言/覆盖支持、回归方式及具体工具路径。
- 里程碑任务量、日期、性能指标与覆盖验收阈值，基于可运行环境细化，不虚构保证。
